# Music Gift

Music Gift — небольшой статический сайт цифровых музыкальных открыток. Получатель касается NFC-метки смартфоном или открывает полученную ссылку и попадает на персональную страницу с коротким сообщением и музыкой.

Проект не является каталогом или стриминговым сервисом. В нём нет backend, базы данных и CMS: страницы собираются заранее и публикуются как статические файлы.

## Стек

- Next.js с App Router
- TypeScript
- Tailwind CSS
- статический export
- GitHub Pages и GitHub Actions

## Структура

```text
app/                  маршруты, layout и глобальные стили
app/gift/[slug]/      статический маршрут подарка
components/           UI музыкальной открытки
content/gifts/        данные подарков и их реестр
lib/paths.ts          добавление basePath к публичным ресурсам
types/gift.ts         типы Gift, Track и Scripture
public/images/        локальные обложки
public/audio/         локальные аудиофайлы
.github/workflows/    публикация на GitHub Pages
```

## Локальный запуск

Требуется Node.js 20.9 или новее.

```bash
npm install
npm run dev
```

Откройте `http://localhost:3000`. Демонстрационные открытки доступны по адресам `/gift/anxiety/`, `/gift/hardship/` и `/gift/not-alone/`.

Поддерживаются два сценария: один выбранный трек как личная музыкальная открытка и несколько треков как небольшой тематический путь или плейлист. Оба сценария используют одну модель данных и один шаблон страницы.

## Проверки и сборка

```bash
npm run lint
npm run build
```

Команда `npm run build` создаёт статический сайт в каталоге `out/`. Динамические страницы подарков перечисляются функцией `generateStaticParams()`, поэтому для каждого зарегистрированного slug создаётся отдельный HTML-файл. Повторяющиеся slug останавливают сборку с явной ошибкой.

В режиме разработки неизвестный slug обрабатывается через `notFound()`. В статическом export серверного кода нет: Next.js создаёт общий `out/404.html`, а GitHub Pages отдаёт его с HTTP-статусом 404 при прямом открытии любого неизвестного URL. Исходный URL остаётся в адресной строке, но `generateMetadata()` и `notFound()` для него на хостинге уже не выполняются. SPA-fallback для этого не требуется.

## Как добавить подарок

1. Создайте файл `content/gifts/new-gift.ts` и экспортируйте из него объект типа `Gift`.
2. Добавьте объект в массив `gifts` в `content/gifts/index.ts`.
3. Поместите обложку в `public/images/` и укажите путь вида `/images/new-gift-cover.svg`.
4. Запустите `npm run build`. Страница появится по адресу `/gift/new-gift/`.

Менять компоненты для нового подарка не требуется.

## Обложки и аудио

Обложки хранятся локально в `public/images/`. Для SVG предпочтителен `viewBox`; текст и внешние ресурсы внутри файла не нужны.

Для короткого фрагмента используйте режим `preview`:

```ts
{
  mode: "preview",
  title: "Название",
  audioPreview: "/audio/name-preview.mp3",
  externalLinks: { youtube: "https://..." }
}
```

Для полного локального трека используйте режим `full`:

```ts
{
  mode: "full",
  title: "Название",
  audioFull: "/audio/name.mp3"
}
```

Если путь к аудио не указан, компонент не создаёт `<audio>` и показывает нейтральный placeholder. Разработчик самостоятельно отвечает за наличие прав на размещаемые аудиофайлы.

Нативные проигрыватели сохраняют стандартные доступные элементы управления. При запуске одного трека остальные проигрыватели на странице автоматически ставятся на паузу.

## GitHub Pages

Workflow `.github/workflows/deploy.yml` запускается при push в ветку `main`, проверяет код, выполняет статическую сборку и публикует `out/` через GitHub Pages.

В настройках репозитория выберите **Settings → Pages → Source → GitHub Actions**.

Для project page workflow автоматически передаёт `NEXT_PUBLIC_BASE_PATH=/<repository>`; для репозитория `<owner>.github.io` оставляет путь пустым. Поэтому одна конфигурация работает и в корне домена, и в подкаталоге без привязки к конкретному имени репозитория.

Для ручной проверки project page локально:

```bash
NEXT_PUBLIC_BASE_PATH=/repository npm run build
```

В PowerShell:

```powershell
$env:NEXT_PUBLIC_BASE_PATH='/repository'; npm run build
```

`next.config.ts` нормализует переменную и применяет её как `basePath` и `assetPrefix`. Внутренние переходы используют `next/link`, а пути к локальным изображениям и аудио проходят через `publicPath()`.

## Ограничения MVP

- контент добавляется вручную в TypeScript-файлы;
- нет backend, CMS, базы данных, аналитики и пользовательских аккаунтов;
- нет загрузки аудио через интерфейс;
- нет PWA и офлайн-режима;
- используются нативные возможности HTML5 audio без сложного управления очередью или прогрессом;
- GitHub Pages отдаёт заранее собранные страницы и стандартный статический 404.
